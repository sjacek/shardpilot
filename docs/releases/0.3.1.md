# ShardPilot 0.3.1

[Release guide](../releases.md) · [Changelog](../../CHANGELOG.md) · [Previous release](0.3.0.md)

Project version: `0.3.1`. Release tag: `v0.3.1`.

## Homepage metadata fix

The core and Maven adapter now declare `https://github.com/sjacek/shardpilot` directly in their
published POMs. Version 0.3.0 inherited that URL from `shardpilot-parent`; Maven could resolve it,
but artifact listings reading only a child POM could not find a homepage. The parent already
declared the URL. All three native Maven publications now contain it explicitly.

Release-bundle validation checks the direct `project/url` in every uploaded POM as well as the
effective Maven model. Regression cases reject absent and incorrect URLs even when the parent
would supply valid inherited metadata.

This patch changes publication metadata and release checks. Class assignment, timing-history
handling, Gradle/Maven APIs, YAML schemaVersion=1, JSON/HTML reports and test execution are unchanged.
Existing 0.3.0 consumers need only update the plugin version; every shard in a pipeline must use
the same version. No database, manifest or configuration migration is required.

## Upgrade

Gradle Groovy DSL:

```groovy
plugins {
    id 'io.github.sjacek.shardpilot' version '0.3.1'
}
```

Gradle Kotlin DSL:

```kotlin
plugins {
    id("io.github.sjacek.shardpilot") version "0.3.1"
}
```

Native Maven adapter:

```xml
<plugin>
  <groupId>io.github.sjacek</groupId>
  <artifactId>shardpilot-maven-plugin</artifactId>
  <version>0.3.1</version>
</plugin>
```

Retain the existing `select` bindings, Surefire/Failsafe exclusions and standalone aggregation
commands from the [Maven guide](../maven.md). Gradle retains both implementation coordinates
`io.github.sjacek:shardpilot:0.3.1` and the `io.github.sjacek.shardpilot` plugin ID.

## Verification and publication

Before creating the tag, run these local checks with JDK 17 or later:

```shell
./gradlew clean check assemble verifyReleaseTag -PreleaseTag=v0.3.1
./mvnw -B -ntp verify
bash scripts/verify-maven-release.sh
```

The signed-bundle check uses a disposable key, validates all nine artifacts and signatures, and
never uploads. Validate the Portal publication with `./gradlew publishPlugins --validate-only`
when publisher credentials are available. Local verification does not replace the required
12-job compatibility gate for the release commit.

Local verification on 24 October 2026 passed on Windows/Temurin 25.0.4.1: 158 Gradle/core cases,
113 Maven/core cases, all seven Invoker/example projects, the nine-signature bundle check and
Portal `--validate-only`. The core cases are shared between adapters, not distinct additional tests.
See [the recorded verification scope](../testing.md#031-local-release-verification).

The maintainer commits and pushes the release changes, then creates the signed `v0.3.1` tag on
the revision whose CI checks passed. Tag creation starts Gradle publication after the full gate.
After confirming Plugin Portal availability, start Maven publication from the same existing tag:

```shell
gh workflow run publish.yml --repo sjacek/shardpilot --ref v0.3.1
```

This manual run repeats the gate and publishes only Maven Central. Verify both adapters in fresh
consumer projects after publication, including sharded test execution and YAML/HTML artifacts.
Version 0.3.0 and its tag remain unchanged. Record the Portal's actual release date after publication.

## External catalog display names

Gradle Plugin Portal generates the marker POM independently of locally generated publication
metadata. This patch does not change an existing MVNRepository marker title or description;
catalog corrections require a separate request to the catalog administrator. See the
[publication metadata notes](../publication-descriptions.md#verification-and-publication).
